# 2025 最新 ComfyUI 保姆級安裝教學：硬體門檻與 AIGC 入門

## 一句話摘要
針對 ComfyUI 的全方位入門教學，涵蓋從硬體門檻、軟體部署、虛擬記憶體優化到模型安裝與錯誤排除的 AIGC 實作指南。

## 頻道/主講者背景
主講者名為「阿一」，是一位設計師。

## 核心論點
- **開源與閉源的抉擇**：閉源模型（如可林、Sora）操作方便但需付費且自由度有限；開源模型（如 SD、Qwen）只要硬體達標即可免費無限使用，且能透過自定義工作流實現極高的創作自由度。
- **硬體決定創作邊界**：顯存（VRAM）大小直接決定了使用者能進行的操作類型（生圖、編輯或影片生成）。
- **系統層級的穩定性優化**：除了軟體安裝，系統端的「虛擬記憶體」設定是避免 ComfyUI 運行中內存崩潰致卡死的關鍵步驟。
- **工作流驅動的生產力**：ComfyUI 的核心價值在於透過節點搭建複雜工作流，並利用「管理器（Manager）」實現自動化的環境維護與缺失節點修復。

## 關鍵細節與數據
- **硬體需求**：
  - 顯卡優先推薦 NVIDIA（N卡）。
  - **顯存（VRAM）門檻**：生圖需 **8G** 以上、編輯圖片需 **12G** 以上、影片生成需 **16G** 以上。
  - AMD/Intel 顯卡若僅生圖，建議顯存需達 **24G** 以上。
- **虛擬記憶體設定**：建議初始大小設為 **60,000 (60G)**，最大值設為 **120,000 (120G)**。
- **雲端方案**：配置不達標可用雲端平台（如 RunPod），頂級顯卡 4090D 每小時約 **1 塊多（人民幣）**。
- **軟體安裝與組件**：
  - 整合包推薦使用「秋葉」整合版。
  - 安裝路徑必須解壓縮至 **SSD 固態硬碟** 以確保加載速度。
  - 關鍵組件需安裝 **PyTorch**（N卡選 CUDA 版本，A/I卡選 DirectML 版本）及 Python 環境。
- **模型路徑與管理**：
  - 核心模型包含 **clip、底模（Checkpoint）、vae** 三個文件，需分類放入對應資料夾。
  - 報錯處理：使用右上角 **Manager** 的「安裝缺失自定義節點（Install Missing Custom Nodes）」功能自動修復。

## 值得引用的金句
- 「開源模型……只要你電腦配置夠，就等於免費無限用。」——強調開源模型的經濟優勢與硬體依賴。
- 「自由度拉滿。」——形容開源模型搭建複雜工作流時能超越閉源平台的限制。
- 「一刻也不要耽誤，解壓到固態硬碟裡，後續加載速度會快很多。」——強調實作細節對效率的影響。

## 與其他 AI 工具/概念的關聯
- **閉源平台對比**：將開源的 ComfyUI 與 Midjourney、可林 (Kling)、Sora 等閉源平台進行優劣對比。
- **模型生態**：提到開源黑馬 OneMate（人物替換），以及基於 Qwen Image Edit 2.5 訓練的 Lora 實作案例。
- **Workflow Automation**：ComfyUI 的節點式操作體現從單一 Prompt 生成轉向複雜「工作流」的範式，可直接將下載的工作文件拖入介面自動載入邏輯節點。
- **AI Agent 基礎**：透過 Manager 進行節點修復與環境維護，展示 AI 工具趨向自我管理與自動化維護的特徵。
