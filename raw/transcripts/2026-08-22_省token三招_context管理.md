## 一句話摘要
本影片分享了如何透過「丟掉用不到的」、「縮減留下來的」與「善用 Prompt Caching 折扣機制」三招，在節省 Token 開支的同時，為 AI 清除不必要的雜訊，集中其注意力並提升產出品質 [1-3]。

## 主講者背景
主講者為 **Gary Chen**，其 YouTube 頻道名稱為 **Gary Chen**。他自述起初不是很在意 AI 的 Token 花費，但後來發現認真省 Token 能幫 AI 清理出乾淨的工作環境，少去垃圾上下文（Context）的干擾 [1]。

## 核心論點
*   **無記憶 API 與上下文雪球效應**：大語言模型的底層 API 本身沒有記憶 [4]。每一次送出請求時，系統必須在背景把規則、工具說明、歷史紀錄、外部檔案等四層 Context 完整打包重新注入，導致對話越聊越臃腫，這也是 Token 消耗越滾越大的主因 [4]。
*   **縮短 Prompt 或換小模型無法解決痛點**：當對話視窗已累積數萬 Token 的歷史紀錄時，僅縮短當前 Prompt 字數省下的比例微乎其微；而換用理解力不足的小模型一旦出錯，來回重試反而會燒掉更多額度 [2]。
*   **精準控制 Context 的三手心法**：控制 Token 燃燒率不應被動承受，而應主動精準控制這包 Context [2]。這套心法包含「丟掉用不到的（換任務開新對話、善用編輯回溯、精簡工具）」、「縮減留下來的（先搜尋再餵、給結論清過程、縮小輸入與輸出）」以及「善用快取折扣」 [2, 5-7]。
*   **清理 Context 是清除 AI 時代的技術債**：減少沒用的雜訊不只省下真金白銀，更重要的是能消除寫給 Agent 的文字技術債，讓 Agent 注意力更集中、產出品質明顯提升 [1, 3]。

## 關鍵細節與數據
### 四層 Context 結構與雜訊源 [1, 4]
每次按下 Enter 送出請求時，底層 API 會自動打包以下四層內容重新注入模型：
*   **第一層：系統與專案規則**：內建系統提示詞、專案根目錄底下的 **`CLAUDE.md`** 或 **`agent.md`** 檔案、當前環境的 **`git` 狀態**與作業系統資訊 [1, 4]。
*   **第二層：工具使用說明**：內建終端機、檔案讀寫、搜尋功能，以及外接 **`MCP server`** 的名稱與參數描述（光此清單即可能吃掉數千個 Token） [4]。
*   **第三層：對話歷史紀錄**：該對話視窗中聊過的所有內容與 AI 產出的長篇分析、程式碼 [4]。
*   **第四層：外部檔案與執行紀錄**：讀過的原始碼、PDF 或終端機運行的 **`logs`** [4]。

### 快取折扣數據（Prompt Caching）[8]
*   以 **Claude Opus** 而言，一般輸入 100 萬個 Token 的價格為 **5 美元**；若命中快取，後續讀取的價格直接打一折降至 **0.5 美元**，便宜了 **10 倍** [8]。
*   **快取壽命限制**：Prompt Caching 快取壽命通常為 **1 小時**。若同一個 Session 閒置超過一小時未對話，快取即會失效 [8]。
*   **破壞快取的常見動作**：在同一個任務中途更換模型、中途調整模型的思考強度，或中途打開加速模式，皆會導致快取全部失效，必須重新支付全額 [8]。

### 精準控制 Context 的實戰操作 [5-7]
*   **換任務就開新對話**：階段性任務完成後果斷開新視窗，不讓上一個任務的報錯和工具輸出白白消耗後續額度 [5]。
*   **編輯與分支回溯**：打錯字或指令下不清楚時，不要在底下回「不對，我剛打錯了」，應直接編輯原本打錯的指令，或使用 **`rewind`**（回溯）功能磨掉失敗的產出 [5]。
*   **先搜尋再餵給模型**：處理大專案時不要直接把上百頁 PDF 或幾千行代碼全丟進去，應先用搜尋工具找出相關的幾行再餵給 AI，請求消耗能從好幾萬瞬間降到幾百 [6]。
*   **給結論、清過程（Markdown 交接法）**：來回討論敲定最終架構後，應將最終結論整理成一份 **`.md`** 檔案，在全新對話中餵給 AI，避免重複載入淘汰的廢案與冗長討論 [6, 7]。
*   **縮小輸入格式與輸出範圍**：輸入盡量用純文字或程式碼取代肥大截圖；下指令時明確要求「只輸出修改後的段落」，不要讓模型熱心重寫整篇程式碼，因為輸出 Token 的價格比輸入更貴 [7]。

### 交接 Prompt [9]
Gary 在 Patreon 提供專屬 Prompt，貼進聊到一半的對話中，AI 會自動把還有效的決定與未解問題整理成一份「交接文件」，方便在開新 Session 時直接使用 [9]。

## 重要引言
*   「**我自己其實不是很在意 AI 上面花多少錢，但後來我發現當你認真去省 token 的時候，你真正省下來的其實不只是錢，而是幫你的 AI 清出一個更乾淨的工作環境。**」[1]
*   「**用白話來說就是 AI 你說話比較便宜，但你聽 AI 說話比較貴。**」—— 解釋為何要主動限制輸出範圍、不讓模型重寫整篇代碼 [7]。
*   「**要省 token 的話，儘量不要讓同一個 session 空著超過一小時。**」—— 說明 Prompt Caching 的快取壽命機制 [8]。
*   「**在省 token 的同時，其實也是在清理 AI 時代下的技術債，也就是那一行又一行寫給 agent 的文字。**」[3]

## 與其他工具或做法的關聯
*   **Claude Code 與 Cursor 中的工具說明黑洞**：這些 Agent 開發環境中，所有內建終端機、搜尋工具以及外接 **`MCP server`** 的說明文件與參數定義，在每一次送出時都會被全數塞入 Context——掛載過多用不到的 Plugin 或 MCP 服務會無形中吃掉大量 Token [4, 5]。
*   **極簡版「手動 RAG」工作流**：先用搜尋找出相關幾行、再精確餵給 AI，本質上就是一種最輕量、最省錢的手動檢索增強生成工作流 [6]。
*   **跨對話 Session 的狀態維持工作流**：利用交接 Prompt 將進度與規格固化為 Markdown 檔案，在全新 Session 中載入，克服 API 無記憶特性造成的雪球效應 [4, 7, 9]。
