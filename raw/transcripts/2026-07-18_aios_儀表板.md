## 一句話摘要
透過 AIOS 四層架構（Context, Skills, Connectors, Cadence）結合 Claude Design 與 Claude Code，將零散的 AI 工具與自動化腳本整合為具備實戰能力、可供團隊共享的視覺化儀表板 [1-3]。

## 主講者背景
**Jay (JayLuxAI)**：AI 系統導入專家，專注於 AIOS（AI Operating System）框架推廣，擅長利用 Claude Code (Agent SDK) 的開發能力，將 AI 代理從開發環境轉化為具備 UI 介面的生產力工具 [1, 2, 4]。

## 核心論點
*   **解決工具碎片化與切換損耗**：傳統工作流需要在不同網頁、分頁與終端機間切換。透過儀表板，可將自動化流程、資訊流與對話介面整合，降低認知負荷 [1, 2]。
*   **AIOS 是 Agentic Workflow 的底層地基**：強調在寫程式碼之前，必須先定義好記憶（Context）、技能（Skills）、外部連接（Connectors）與執行節奏（Cadence）四層架構 [2, 3]。
*   **介面即產品的轉型**：利用 Claude Design 進行原型設計，再交由 Claude Code 讀取本地代碼庫進行實作，將複雜的腳本包裝成非技術人員也能操作的按鈕 [5, 6]。
*   **從個人工具到團隊系統**：透過 VPS 部署，將原本僅存於本地的 AI 系統升級為 24 小時運作且全團隊共享的協作平台 [2, 4]。

## 關鍵細節與數據
### 1. AIOS 四大核心組件設定
*   **Context（記憶層）**：儲存專案背景、個人偏好與過去決策。
*   **Skills（技能層）**：用自然語言定義業務邏輯，使 AI 可重覆執行（例如：**ME Plan** 三餐規劃）[2, 7]。
*   **Connectors（連接層）**：串接外部工具（如 **YouTube**, **Google Calendar**, **Obsidian**, **Telegram**）的管道 [2, 3]。
*   **Cadence（節奏層）**：利用 **Trigger.dev** 或 **Model** 平台設定每日、每週的定時觸發任務 [3, 7]。

### 2. 開發流程與技術棧
*   **介面設計平台**：使用 `claude.ai/design/`。
    *   設定模式：選取 **template** 並切換至 **prototype** 模式 [5]。
*   **代碼整合方式**：在 Claude 介面點選 `+` -> `link local code` -> `browse` 選取本地專案資料夾進行掃描 [6]。
*   **開發環境架構**：
    *   **前端 (Front-end)**：使用 **Vite**, **React**, **TS** [8]。
    *   **後端 (Back-end)**：使用 **Fast API**，整合 **Claude Agent SDK** [8]。
*   **開發時程**：從設計到生成可用儀表板約耗時 **10 到 15 分鐘** [8]。

### 3. CLI 指令與範例
*   **`/run-aios`**：自訂的 CLI 指令，用於直接在終端機啟動 AIOS 儀表板，免除手動輸入繁瑣指令的過程 [9]。
*   **實測數據**：**ME Plan** 技能成功計算出 **3440 卡路里**與 **237 克蛋白質**，並將規劃結果即時推播至 **Telegram** 頻道 [7, 8]。

## 與其他工具的關聯
*   **Claude Code (Agent SDK)**：作為核心引擎，執行讀取檔案、跑腳本與串接工具的邏輯 [2, 10]。
*   **Trigger.dev / Model**：負責 Cadence 層級的排程觸發機制 [7]。
*   **Telegram**：作為主要的工作流通知輸出端 [7, 8]。
*   **Hostinger / VPS**：用於託管儀表板，實現團隊共享與 24 小時服務 [4]。
*   **Obsidian / Google Calendar**：作為 Connectors 層級串接的知識庫與日程數據源 [3]。
