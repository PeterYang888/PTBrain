這是一份根據 YouTube 頻道「Gary Chen」對 Matt Pocock（MPO）開源 AI 工作流專案的深度拆解所整理的結構化簡報：

## 一句話摘要
透過將深厚的軟體工程底蘊（如 TDD 與深模組架構）轉化為極簡的模組化 Skill，Matt Pocock 展示了如何將充滿隨機性的 AI 從「黑盒子」馴化為具備大局觀的頂級工程師 [1], [2], [3]。

## 主講者背景
*   **頻道名稱**：Gary Chen [1]。
*   **主講者**：Gary Chen，資深技術觀察者，專注於 AI 工作流與開發思維拆解。
*   **專案背景**：介紹 **Matt Pocock (MPO)**，他是 TypeScript 領域的頂尖專家，其開源的 AI Skill 專案在 GitHub 已獲得超過 16 萬顆星，並被下載超過 700 萬次 [1]。

## 核心論點
*   **控制 AI 的隨機性**：AI 本質是隨機的黑盒子，開發的核心挑戰在於如何穩定地控制它，而非單純追求產碼速度 [2]。
*   **極簡模組化優於重型框架**：相較於將開發流程「硬綁定」的重型工具（如 Superpowers），Matt 提倡「隨插即用」的樂高式 Skill，更適合理解力極強的現代模型（如 Claude Fable 5 或 GPT-5.6） [4], [3]。
*   **奪回人類的決策主權**：透過強制 AI 反向拷問人類（/grill-me），防止開發者在模糊想法下進行「Vibe Coding」，確保決策權留在人類手中 [5]。
*   **以 TDD 防止 AI 「作弊」**：規定在寫功能前必須先寫測試。若先寫程式再補測試，AI 常會為了交差而生成一個保證會通過的「假測試」，導致無法抓出 Bug [6]。
*   **對抗邏輯碎片化的「深模組」危機**：AI 缺乏大局觀，易寫出缺乏入口、溝通成本極高的「淺模組」；必須透過重構建立具備簡單門戶、隱藏複雜細節的「生模組（Deep Modules）」 [7], [8]。

## 關鍵細節與數據
### 1. 核心 Skill 清單與功能 [1], [9]
*   **`/grill-me`**：拷問需求，達成共識前嚴禁寫程式。
*   **`/spec`**：將共識轉化為規格書，嚴禁寫入具體程式碼以避免日後混淆 [10]。
*   **`/2-tickets`**：按「使用者功能」而非技術架構拆分任務，確保每步皆可獨立測試 [10], [11]。
*   **`/implement`**：執行實作，自動引導 TDD 流程。
*   **`/code-review`**：開啟乾淨 Session 審查代碼。
*   **`/improve-case-architecture`**：執行架構大掃除，對模組進行「殘酷刪除測試」 [8]。
*   **`/grill-with-docs`**：進化版拷問，會自動記錄專有名詞與決策文件 [9]。

### 2. `/grill-me` 的五行 Prompt 原文 [2], [5]
1. "叫 AI 在我們對接下來的計畫沒有達成共識之前把我往死裡問。"
2. "它要 AI 像是在畫心智圖一樣，順著你的思路去延伸把你每一個決定背後會引發的連鎖反應一個一個抓出來問到底。"
3. "要求 AI 每次只能問一個問題。"
4. "而且必須附上建議答案。"
5. "嚴格規定在整體設計達成共識之前，絕對不准偷跑去寫程式。"

### 3. Code Review 的 12 種「壞味道」診斷（源自《重構》） [12]
*   **Shotgun Surgery (散彈槍修改)**：改一個功能要動十幾個檔案。
*   **Feature Envy (特性依戀)**：邏輯放錯檔案。
*   **Data Clumps (資料泥團)**：總是同時出現的變數應打包成物件。

### 4. 數據與規格 [1], [13], [9]
*   **專案熱度**：16 萬星，700 萬次下載。
*   **錄製限制**：`Record & Replay` 功能最大錄製時長為 30 分鐘（視為另一種 Skill 形式）。
*   **Prompt 壓縮三原則**：修剪（Pruning）、指引詞（Indexing，利用專業術語如 `data clumps` 壓縮資訊）、完成標準（Completion）。

## 重要引言

## 與其他工具的關聯
*   **Superpowers**：早期模型的「保姆級」防呆流程，具備寫死的九個步驟；相較之下，MPO 的 Skill 是「樂高積木」，適合聰明模型且不綁架流程 [4], [3]。
*   **Claude Code / Agent SDK**：MPO 的專案等同於一套基於 Agent 思維的開發框架，將軟體工程實踐封裝進 Skill 裡。
*   **Vibe Coding**：主講者將其定義為「把模糊想法丟給 AI 平感覺做」，而 Matt 的工具正是為了終結這種高風險的開發模式 [5]。
*   **HTML over Markdown**：提及 Anthropic 工程師偏好用 HTML 溝通，這與 Matt 追求精準、極簡的 Prompt 哲學一致 [13]。
