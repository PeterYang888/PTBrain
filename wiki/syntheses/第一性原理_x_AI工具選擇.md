# 用第一性原理框架選 AI 工具

> 把「第一性原理四步落地法」套用在 AI 工具 / 模型選擇上，得出一套不依賴口碑與跟風的決策流程。

## 為什麼這個問題值得用第一性原理？

AI 工具的選擇，目前大多數人靠的是**類比思維**：
- 「大家都在用 GPT-4，我也用」
- 「Opus 是旗艦所以最好」
- 「Claude Code 很紅，裝了再說」

這正是[[第一性原理]]要打破的模式。工具選擇的底層問題不是「哪個最強」，而是「我的任務需要什麼，哪個工具的邊界條件剛好符合？」

---

## 四步落地：AI 工具選擇版

### Step 1｜定義真問題（5 Whys）

不要問：「我應該用哪個 AI？」

要問：
- 我在解決什麼任務？（寫程式 / 分析文件 / 對話 / 自動化）
- 任務的頻率？（一次性 vs. 每天幾百次）
- 延遲容忍度？（等 30 秒 OK vs. 需要即時）
- 對「出錯」的容忍度？（草稿可以錯 vs. 醫療/法律不能錯）

### Step 2｜物理級拆解（找不可妥協的邊界）

AI 模型的「物理邊界」是：

| 維度 | 實際邊界 |
|------|---------|
| 推理深度 | 問題需要多少層邏輯跳躍？ |
| Context 長度 | 一次要塞進多少文字？ |
| 速度 | 使用者等待的上限是幾秒？ |
| 成本 | 每次呼叫的可接受費用上限？ |
| 思考模式 | 需要[[延伸思考]]還是快速反應？ |

這些是**不能靠口碑解決**的問題，只能靠實測數字。

### Step 3｜無規限推導（忘掉品牌，從邊界組合）

根據[[2026-04-16_claude_模型選擇指南]]的模型分層：

```
高推理需求 + 長 context + 可等待 → Claude Opus 4.6
日常開發 + 平衡速度與智慧      → Claude Sonnet 4.6
高頻 / 輕量 / 成本敏感         → Claude Haiku 4.5（官方：先從這裡起跑）
```

關鍵推論：**大多數任務的「物理需求」根本不需要旗艦模型**。選 Opus 通常是類比思維（「最好的就是最好」），不是第一性原理。

### Step 4｜MVP 驗證

- 先用最便宜的模型跑，記錄失敗的具體案例
- 只在出現「因推理不足導致的真實錯誤」時才升級
- 不要因為「感覺不夠聰明」升級——這是直覺，不是數據

---

## 核心結論

> **類比思維選工具**：選最紅的、選最貴的、選別人推薦的。  
> **第一性原理選工具**：列出任務的物理邊界 → 找剛好滿足邊界的最低成本選項 → 測試 → 只在有具體失敗證據時才升級。

這個邏輯不只適用於 Claude，對所有 AI 工具（GPT / Gemini / 本地模型）都成立。

## 延伸問題（待探索）

- 「穩定期 vs. 變動期」的判斷標準是什麼？AI 工具領域目前明顯處於變動期，第一性原理更重要——但何時會進入穩定期？
- [[routines]] 的自動化場景：在設計自動化 pipeline 時，模型選擇的成本槓桿更大，值得單獨做一篇分析
