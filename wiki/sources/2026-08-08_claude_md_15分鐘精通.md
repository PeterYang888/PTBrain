# 15 分鐘學完 CLAUDE.md：從入門到精通

> 來源：[原始檔](../../raw/transcripts/2026-08-08_claude_md_15分鐘精通.md) · 主講：[[Gary_Chen]]

## 一句話摘要
把 `CLAUDE.md` 當成有限的**指令預算（Instruction Budget）**來經營——用層級化設計分流規則、用減法修剪冗餘、把長流程交給 Skill、把死罪交給 Hook，並隨模型變強持續刪規則。

## 核心論點
- **`CLAUDE.md` 是最高指導原則**：對話啟動時自動注入 Context Window，省去每次重複解釋專案架構（[[Context_工程]] 的具體實踐）
- **三層級規則設計**：User-level（個人長期偏好）→ Project-level（專案共同標準，隨 Git 上傳）→ Nested-level（子資料夾專屬，如 `frontend` React 與 `backend` Python 各放一份）；規則依序疊加，「放得越接近實際工作的檔案，適用範圍就越精確」
- **不要寫 AI 自己查得到的東西**：`/init` 生成的範本常塞入 explorer subagent 本就會掃描的客觀資訊（如 `package.json` 內容），浪費 Token 又佔用指令預算
- **指令預算是真實限制**：AI 單次任務能同時顧及的規則數量有限，冗餘指令迫使模型分心去裁決衝突與優先序，真正重要的核心規則反而被淹沒
- **寫入門檻＝隱性知識**：只有「AI 翻程式碼也猜不出來的東西」才夠格寫進去
- **資訊分流三選一**：長且特定任務才需要的流程 → 寫成 `skill`；絕對不能犯的死罪（如 commit API key）→ 用 **hook** 在 commit 前程式強制攔截，而非靠 Markdown 提醒
- **花園式維護**：「一份好的 CLAUDE.md 就像一個花園，維護工作只有兩件事：新增與修剪」——用 `/insights` 分析歷史對話產 HTML 報告來找候選規則

## 關鍵細節
- **檔案層級**：`CLAUDE.md`（專案設定檔，隨 Git 上傳）｜`CLAUDE.local.md`（僅留本機、不上傳的個人偏好）｜`agent.md`（[[OpenAI_Codex]] 的對應檔）
- **指令**：`/init`（掃描專案生成第一版範本）｜`/insights`（分析歷史對話，產出規則／Skill／Hook 的優化建議 HTML 報告）
- **雙工具同步法**：在 `CLAUDE.md` 第一行直接 reference `agent.md`，用單一源頭（Single Source of Truth）同時餵 Claude Code 與 Codex
- **五個加法問題**：用「絕對禁忌／聯動關係／定義完成」等提問，把腦中經驗榨成規則
- **80% 數字**：官方團隊為新模型優化系統提示時一口氣刪掉超過 **80%** 的規則，能力沒有退步——證明模型變聰明後，舊規則會反過來變成限制
