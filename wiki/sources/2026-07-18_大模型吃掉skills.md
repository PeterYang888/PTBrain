# 大模型開始吃掉 Skills

> 來源：[原始檔](../../raw/transcripts/2026-07-18_大模型吃掉skills.md) · [[黃一河]]（huangyihe）

## 一句話摘要
隨著模型自主規劃能力飛躍（如 [[Claude_Fable_5]]），為彌補模型智力不足而生的重型 prompt 與垂直 Skills 正被淘汰；Skill 的存留價值轉向「判斷力固化」與輕量工具入口。

## 核心論點
- **模型進化蠶食垂直 Skills**：實測 Fable 5 不用 PPT skill、直接「手搓」Python 腳本做 PPT，10 分鐘產出 10 頁、視覺邏輯連貫
- **拆除冗餘重型外掛**：「Superpowers」式長 prompt 過於笨重、燒 Token，應簡化或刪除；模型越強，越多通用能力交還底層模型
- **從執行外包轉向判斷固化**：Skill 的核心價值是把人類想清楚的方法論與判斷體系固化，讓模型穩定執行人的意志
- **Skill 的未來是輕量入口**：短路由、少量邊界、按需參考資料、可執行腳本、明確驗證——而非教模型當專家的長文

## 五種仍有價值的 Skill 類型
1. **工具操作型**：調用本地 CLI / API / [[MCP]]（例：Whisper 時間碼 → FCPXML → 達芬奇導入）
2. **方法論型**：固化判斷體系（例：七層產業鏈投資方法論）
3. **高風險約束型**：限定數據來源優先級與時效要求
4. **確定性生產型**：輸出必須機器可驗證，生成代碼轉為執行已驗證腳本
5. **項目知識與組織協作型**：規範命名、目次、交付、歸檔

## 值得引用的段落
> 「模型越強，越多通用能力會被它吃掉。」

> 「未來的 Skill 更像一個輕量操作系統入口……而不是一篇教模型如何成為專家的長提示。」

> 「如果你外包的是審美判斷、問題的定義和價值排序……你就是在一點一點地放棄自己的主體性。」
