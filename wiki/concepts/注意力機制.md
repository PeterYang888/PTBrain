# 注意力機制（Attention）

> [[Transformer]] 的核心運算：讓序列中的每個 Token 依「誰跟我相關」動態分配權重，跨越距離抓取上下文關聯。

## QKV 三角色
| 角色 | 直覺 |
|---|---|
| **Query（Q）** | 我在找什麼 |
| **Key（K）** | 我能提供什麼 |
| **Value（V）** | 匹配成功後交出的實際資訊 |

運算：Q 與 K 做**縮放點積（Scaled Dot-product）**，再經 **Softmax** 轉成權重，用來加權平均 V。

典型效果：預測下一個詞時，動詞能跨越距離找到它的主語。

## 為什麼需要位置編碼
注意力本身**不具順序感**——它看的是內容相似度，不是先後。

> 「嵌入只編碼了這個 Token 是什麼，完全不知道這個 Token 在序列裡的位置。」

因此必須另外注入[[位置編碼]]。

## 變體與效率優化
- **多頭注意力（Multi-Head Attention）**：多組 QKV 平行運算，捕捉不同類型的關聯
- **GQA（分組查詢注意力）**：多個 Query Head 共用少量 KV Head。LLaMA-2 70B 為 64 Query Head ／ 8 KV Head，大幅壓縮 KV cache
- **FlashAttention、稀疏注意力**：降低 $O(n^2)$ 的計算與記憶體代價

## Induction Heads
2022 年 [[Anthropic]] 發現的注意力頭類型，用來解釋 **in-context learning**（模型能從提示詞中的範例即時學會模式）的機制來源。

## 已知限制
- **$O(n^2)$ 複雜度**：計算量隨序列長度平方成長
- **Lost in the Middle**：長上下文中，提示詞中段的資訊處理可靠度低於開頭與結尾

## 與其他概念的關係
- 與 FFN 分工：注意力負責 Token **之間**交換資訊，FFN 負責 Token **各自**深加工（見 [[Transformer]]）
- [[位置編碼]] 是它的必要補件
- [[MoE]] 作用在 FFN 層，與注意力層正交
