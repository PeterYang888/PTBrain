# 位置編碼（Positional Encoding）

> 因為[[注意力機制]]本身不具順序感，必須額外把「Token 在序列中的位置」注入模型的資訊管道。

## 為什麼需要
Embedding 只回答「這個 Token 是什麼」，完全不含「它在第幾個位置」。少了位置資訊，「狗咬人」與「人咬狗」對模型是同一件事。

## RoPE（旋轉位置編碼）
- **2021 年**由蘇劍林等人提出，現代 LLM 的主流做法
- 原理：**旋轉向量的角度**來編碼位置，使兩個 Token 的內積自然反映其**相對位置**關係
- 相對於原始 Transformer 的絕對位置編碼（2017），RoPE 在長序列外推上表現更好

## 已知限制：Lost in the Middle
即便有 RoPE，模型對提示詞**中段**內容的處理仍不如開頭與結尾可靠。這是長上下文應用（如把整份文件塞進 prompt）的實務陷阱：關鍵資訊該放頭尾。

## 與其他概念的關係
- 是 [[Transformer]] 前處理階段的必要組件，緊接在 Embedding 之後
- 直接服務於 [[注意力機制]]——沒有它，注意力無法區分語序
- 對 [[Context_工程]] 有實務意涵：長 context 不等於均勻可用，重點資訊應置於頭尾
