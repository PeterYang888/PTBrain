# Prompt Caching（提示詞快取）

> AI 模型商將對話中重複出現的提示詞內容暫存在伺服器上，命中快取時讀取價格大幅打折的機制。

## 詳細說明
主流模型（Claude、OpenAI 等）背後都有 Prompt Caching：把同一段 context（如系統提示詞、`CLAUDE.md`、前幾輪對話）快取在伺服器端，後續請求若能命中快取，就不需要用原價重新處理這段內容（見 [[2026-08-22_省token三招_context管理]]）。

## 關鍵特徵 / 組成
- **價格差距**：以 Claude Opus 為例，一般輸入 100 萬 token 約 5 美元；命中快取後降到 0.5 美元，便宜 10 倍
- **快取壽命**：通常約 1 小時。同一 session 閒置超過一小時未對話，快取即失效
- **會破壞快取的動作**：同一任務中途換模型、中途調整思考強度、中途開啟加速模式——這些都會讓已累積的快取全部失效，需重新支付全額

## 與其他概念的差別
- 跟 [[Context_工程]] 的差別：Context 工程管的是「該不該把這段內容送進去」，Prompt Caching 管的是「同一段內容重複送進去時能不能打折」——一個是內容層面的取捨，一個是價格層面的槓桿
- 跟 [[指令預算]] 的差別：指令預算管模型的注意力稀缺，Prompt Caching 純粹是金錢成本機制，兩者互不影響

## 應用 / 實例
- 在 [[Gary_Chen]] 的省 token 三招中，「善用快取折扣」是丟棄與縮減之外的第三招：建議不要讓同一 session 閒置超過一小時，且避免任務中途切換模型/思考強度，以維持快取有效

## 爭議 / 未定論
