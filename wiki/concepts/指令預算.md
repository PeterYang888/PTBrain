# 指令預算（Instruction Budget）

> AI 在單次任務中能同時「真正顧到」的規則數量有限。規則檔不是越詳盡越好——冗餘指令會迫使模型分心裁決衝突與優先序，把核心規則淹沒。

## 詳細說明
[[Context_工程]] 談的是 context window 的 **Token** 稀缺；指令預算談的是同一份 context 裡**注意力**的稀缺。兩者不同：一條規則就算 Token 很便宜，只要它存在，模型每次任務都得判斷「這條適不適用、跟別條衝不衝突」。所以規則檔的優化目標不是「寫滿」而是「寫準」。

出處：[[Gary_Chen]] 在 [[2026-08-08_claude_md_15分鐘精通]] 提出，用於 `CLAUDE.md` / `agent.md` 的撰寫與維護。

## 三個操作原則

### 1. 分層放置，越近越精確
| 層級 | 放什麼 | 位置 |
|---|---|---|
| User-level | 個人長期偏好（如輸出語言、思考框架） | 使用者目錄 |
| Project-level | 專案共同標準，隨 Git 上傳給團隊 | 專案根目錄 `CLAUDE.md` |
| Nested-level | 子資料夾專屬（`frontend` React vs `backend` Python） | 各子資料夾 |
| 本機私有 | 不上傳的個人工作偏好 | `CLAUDE.local.md` |

規則依序疊加。「規則放得越接近實際工作的檔案，適用範圍就越精確。」

### 2. 分流：不是所有知識都該進規則檔
- **AI 自己查得到的 → 不寫**：專案結構、`package.json` 內容等，explorer [[Subagent]] 本來就會掃描
- **長且特定任務才需要的 → 寫成 Skill**（呼應 [[Skill_輕量化]] 的樂高式組裝）
- **絕對不能犯的死罪 → 寫成 Hook**：如 commit API key，用程式在 commit 前強制攔截，而非靠 Markdown 提醒模型自覺
- **剩下的隱性知識才寫進規則檔**：判準是「AI 翻程式碼也猜不出來的東西」

### 3. 花園式維護：只有新增與修剪
- **加法**：用「絕對禁忌／聯動關係／定義完成」等提問，把腦中經驗榨成規則
- **減法**：模型變強後，舊規則會反過來變成限制。官方團隊為新模型優化系統提示時曾一口氣刪掉超過 **80%** 的規則而能力未退步（[來源口述，未查證]）

## 與其他概念的關係
- 是 [[Context_工程]] 在「規則檔」這一面向的具體化：Context 工程管 Token，指令預算管注意力
- 與 [[Skill_輕量化]] 是同一主張的兩端：後者說「Skill 本身要小」，本頁說「主規則檔要小、細節外移到 Skill」
- 與 [[工具無關性]] 呼應：`CLAUDE.md` 第一行 reference `agent.md`，用單一源頭同時餵 [[Claude_Code]] 與 [[OpenAI_Codex]]
- 對比 [[Vibe_Coding]]：Vibe Coding 靠對話臨場交代，指令預算主張把重複交代的部分固化、把一次性的部分留在對話
